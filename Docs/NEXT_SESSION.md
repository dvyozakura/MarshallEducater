## 1. 【バグ】ログイン切れを見分けられない
- 症状: Claude Code のログインが切れると `claude -p` は次の文言で終わる(実際に出たもの)。アプリがこれを「未ログイン」と判定できるようにする。
  - `Failed to authenticate: OAuth session expired and could not be refreshed`
  - `Prompt is too long · automatic compaction failed: Failed to authenticate: OAuth session expired and could not be refreshed`
- 案内の文言: 「ターミナルで claude を起動し、/login でログインし直してください」。
- 確認: 偽 Claude でこの2つの文言を返させ、未ログインの案内が出る単体テスト。

## 2. 教材のデータと目次
- CLAUDE.md「体系的な教材」と「データの置き場所」の textbook/ の型を定義し、検証つきで読み書きする。
- 単元ツリーから目次を作る。章の状態(未作成/作成中/完成/作り直しを提案)、既読の印、単元ごとの「未習」の印。
- 既存の授業ノートは、該当する章の補足として目次から開けるようにする(消さない)。
- 確認: 単体テスト(目次の生成、単元ツリーが後から変わったときの追従、状態の保存)。

## 3. 章の生成と点検
- 1章 = 1ジョブ。プロンプトには、目標・難易度、その単元の習熟度とミスの種類の傾向、未習かどうか、志望校の傾向(あれば)、前後の章の題を渡す。
- 厚さの決め方(習熟度 → 詳しさ・例題の数)は暫定で決めて DECISIONS に記録。
- 例題と確認問題は、セッション1の「問題の作成と検算」の仕組みを通す。
- 本文は別の呼び出しで事実・計算・用語を点検し、指摘があれば1回直してから完成にする。点検結果を review/ に保存し、設定の「品質」欄に数を出す。
- 「まとめて作る」: 未作成の章を順にジョブへ入れる。始める前に呼び出しの見込み数を表示して確認を取る。1日の上限を超える分は翌日に回す。
- 作り直すときは前の版を versions/ に残す。苦手マップが大きく変わった章に「作り直しを提案」を付ける(しきい値は暫定)。
- 確認: 偽 Claude で、生成 → 点検で指摘なし/指摘あり→修正/検算で問題を差し替え、の各通り。まとめて作るの上限またぎの単体テスト。

## 4. 科目ページの「教材」タブと読む画面
- 各科目のページに「教材」タブ。目次、章ごとの状態と「作る/作り直す」ボタン、まとめて作る、既読・未習の切り替え。
- 章を読む画面(Markdown+KaTeX、図は SVG)。前の章・次の章への移動、既読にする、章または科目全体の PDF 出力。
- 生成中の章は、ジョブの進み具合を目次に出す。
- 確認: 自動操作テストで、タブを開く → 章を作る → 読む → 既読 → 再起動後も残る → PDF が出る。

## 5. 教材への質問
- 章を読む画面の横に質問欄。文章を選んで「ここを質問」で、選んだ箇所を引用して質問できる。
- 文脈として、その章の本文・選んだ箇所・その単元の苦手マップ・プロジェクトの目標を渡す。会話は章ごとに保存し、続きができる(セッション1の質問の仕組みを使い回す)。
- 「教材に反映」: 会話をもとに、その章へ補足を追記させる(追記前の版は versions/ に残す。追記分も点検を通す)。
- 科目ページの「教材」タブからも、章を指定せずに科目全体について質問できる(文脈は目次と苦手マップ)。
- 確認: 自動操作テストで、選択して質問 → 2往復 → 再起動後も会話が残る → 教材に反映で章が更新される。

## 6. 確認問題を既存の流れにつなぐ・本物での確認
- 章の確認問題を「解く → 提出 → 採点 → 苦手マップ更新」に流せるようにする(アプリ内で解く/紙で解く、どちらも)。結果は目次に「確認問題: 何問中何問」と出す。
- 学習計画と今日の課題に「教材の第N章を読む」を入れられるようにする(未習・苦手の単元を優先)。
- `Tools/smoke_real.sh` に教材の最小確認を足す: 1つの章を作る → 点検 → その章に1回質問(本物の呼び出しは5回以内)。1回だけ実行し、出力の質(長さ、数式、誤りの有無で気づいた点)を PROGRESS.md に書く。直せるものは直す。
- 確認: 偽 Claude の自動操作テスト+上の本物の確認1回。
