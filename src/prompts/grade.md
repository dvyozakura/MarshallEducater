# 採点

科目「{{subjectName}}」のテスト「{{testTitle}}」の答案を採点してください。

入力ファイルの内容:

- `project` … 志望校・試験の型・目標の高さ。
- `timeLimitMin` / `elapsedMin` … 制限時間と、実際にかかった時間(分。分からなければ null)。
- `items` … 採点する設問の一覧。設問ごとに:
  - `problemId`、`number`、`format`(choice / short / essay)、`unitName`、`difficulty`、`points`(配点)
  - `body`(問題文)、`choices`(選択肢)、`key`(正解・模範解答)、`rubric`(採点基準)、`solution`(解き方)
  - `answer` … 受験生の答案。選択式は選んだ選択肢の番号。

## 採点の決まり

- `items` の **すべての設問** について、同じ `problemId` で1つずつ結果を書く。
- `score` は 0 以上、その設問の `points` 以下。
  - 選択式: 正解と同じ番号なら満点、違えば 0 点。
  - 短答: 内容が正解と同じなら満点(書き方の違い、同値な式、漢字とかなの違いは正解にする)。違えば 0 点。`rubric` に部分点の決まりがあればそれに従う。
  - 記述: `rubric` に照らして **部分点** を付ける。結論が違っても、正しい立式や考え方には点を与える。
- `rationale` は採点の根拠。記述は部分点の内訳(例: 「立式 4/4、計算 2/4(符号の誤り)、結論 0/2」)。満点なら短くてよい。
- 公平に、しかし厳しすぎずに採点する。答案に書かれていないことを推測で補って加点しない。読み取りの誤りと思われる不自然な文字があっても、書かれているとおりに採点する。
- 減点・間違いがある設問には、`mistake`(ミスの種類)を必ず1つ付ける:
  - `knowledge` … 知識不足(公式・用語・事実を知らない、覚え違い)
  - `approach` … 方針が立たない(何を使えばよいか分からない、解き方の筋が違う)
  - `calculation` … 計算・処理ミス(方針は合っているが、計算・符号・転記・単位などを誤った)
  - `misread` … 読み違い(問題文や条件、設問の要求を取り違えた)
  - `timeout` … 時間切れ(途中まで合っていて、時間が足りず書き切れていない。`elapsedMin` が `timeLimitMin` に達しているときに考える)
  - `blank` … 未解答
- 満点の設問は `mistake` を null にする。
- `comment` は「なぜ間違えたか」の短い所見(1〜2文、受験生に向けて)。答案のどこでつまずいたかを具体的に書く。満点なら空文字でよい。
