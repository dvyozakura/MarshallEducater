# 問題の作成({{purpose}})

科目「{{subjectName}}」の問題を作ってください。用途は「{{purpose}}」です。

入力ファイルの内容:

- `project` … 志望校・試験の型・目標の高さ・試験日。
- `requests` … 作る問題の注文の一覧。**1つの注文につき1問**。
  - `unitId` / `unitName` … 出題する単元。
  - `difficulty` … `easy`(易: 基本の確認)/ `standard`(標準: 入試の標準的な問題)/ `target`(目標校レベル: 志望校の合否を分ける水準)。
  - `format` … `choice`(選択式)/ `short`(短答: 数値・式・語句を答える)/ `essay`(記述: 説明・論述・証明・途中の考え方も書かせる)。
  - `origin` … 何のための問題か(診断 / 苦手克服問題 / 過去問の類題 / 復習 など)。
  - `mistake` … null でなければ、この受験生がこの単元でよくするミスの種類。そのミスを直す練習になる問題にする。
  - `reference` … null でなければ、前に間違えた問題。**同じ問題にはせず**、同じ考え方を別の数値・別の場面で問う類題にする。
  - `avoid` … null でなければ、前回作って不採用になった問題とその理由。同じ失敗をしない別の問題にする。
  - `noFigure` … true なら、図が要らない問題にする。
- `trend` … 志望校の傾向(まだ無ければ null)。あれば、出題形式・言い回し・分量をこれに寄せる。

## 問題の決まり

- `problems` は `requests` と **同じ数・同じ順**。各要素の `unitId`・`difficulty`・`format` は注文のとおりに書く。
- **答えが1つに決まる** 問題にする。条件不足、複数の答えがありうる問題、問題文だけでは解けない問題は作らない。作ったあと、自分で最初から解き直して答えを確かめる。
- `body` は問題文(Markdown、数式は LaTeX で `$...$`・`$$...$$`)。受験生がこれだけ読んで解けるように、必要な条件・資料文・語注はすべて入れる。答えやヒントは書かない。
- 選択式: `choices` に選択肢を2つ以上(ふつう4つ)入れ、正解はちょうど1つ。`answer` は正解の選択肢の番号(1始まり、例: `"3"`)。選択肢の文に番号や記号は付けない(アプリが付けます)。
- 短答: `choices` は空。`answer` は最終的な答え(例: `"$x = 2, 3$"`、`"関ヶ原の戦い"`)。別の書き方でも正解になるものは `rubric` に書く。
- 記述: `choices` は空。`answer` は模範解答。`rubric` に、部分点の付け方を要素ごとに書く(例: 「立式 4点、計算 4点、結論 2点」)。
- `points` は配点(1問 5〜20 点を目安に、難しさと手間に合わせる)。
- `solution` は解き方の説明(受験生が読んで分かるように、考え方 → 手順)。
- 図が無いと出題できない問題だけ、`figureSvg` に SVG を書く(`<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 幅 高さ">` で始め、線・文字は黒、幅 400 以内、スクリプトや外部の画像は使わない)。図が要らなければ null。図に頼らず文章で条件を言い切れるなら、図は付けない。
- 実在の入試問題・市販教材の文章や問題をそのまま写さない。英語・国語の読解用の文章も自分で書く。
- 用途が「実力診断」のときは、短い時間で実力の位置が分かるよう、1問を重くしすぎない。
