# 学習計画の作成

この受験生の、試験日までの **週ごとの学習計画** を作ってください。{{revisionNote}}

入力ファイルの内容:

- `project` … 志望校・試験の型・目標の高さ・試験日。`today` … 今日の日付。`dailyMinutes` … 1日に使える学習時間(分)。
- `weeks` … 計画を立てる週の一覧(`index`、`start`〜`end`、`days`: その週の日数、`mock`: 通しの模擬試験を行う週なら true)。**この一覧と同じ数・同じ順で** 週の計画を返す。
- `beyond` … true のとき、試験日は `weeks` の最後よりさらに先(遠い先は、近づいてから計画し直す)。
- `subjects` … 科目ごとの状況:
  - `mastery`(科目全体の習熟度 0〜100。まだ記録が無ければ null)、`targetMastery`(目標)
  - `weakUnits`(弱い単元: `unitId`、`unitName`、`mastery`、`mistake`: よくするミス)
  - `untestedUnits`(まだ一度も出題していない単元の数)
  - `units`(出題の対象の単元: `id`、`name`、`weight`: 1=ふつう、2=重点、3=最重点)
  - `trend`(志望校の傾向の要点。まだ無ければ null)
  - `textbook`(この科目の教材: 章の数 `chapters`、既読の数 `read`、まだ読んでいない章を読む順に並べた `toRead`: `unitId`・`no` 第何章・`title`・`reason` 理由(未習・苦手・目次の順)・`built` もう作ってあるか)
- `progress` … 作り直しのとき: これまでの計画の進み具合(やれた日数・やれなかった日数、作り直しの理由)。初めてなら null。

## 計画の決まり

- 各週について、`theme`(その週のねらい。1文)と、`items`(科目ごとの取り組み)を書く。
- `items` の1要素は1科目。`subjectId` は入力の `subjects` の `id`。`unitIds` はその週に取り組む単元(その科目の `units` の `id` だけ、1〜4個)。`minutes` はその週にその科目へ使う時間(分)。`goal` は到達の目安(1文。例: 「漸化式の基本3型を迷わず解ける」)。
- `chapterUnitIds` は、その週に読む教材の章(`textbook.toRead` の `unitId` だけ。0〜3個)。**未習・苦手の単元の章を優先** し、`unitIds` で取り組む単元と合わせる(読んでから演習する流れにする)。前半の週に多めに入れ、後半は演習中心にして減らす。読む章を入れた週は `goal` に「教材の第N章を読む」と書き添えてよい。`toRead` が空なら空の配列。
- 1週間の `minutes` の合計は、`dailyMinutes × days` を超えない。**8割ほどに抑えて余裕を持たせる**(できない日があっても破綻しないように)。
- 優先順位: ①弱い単元(`weakUnits`)のうち重みが大きいもの ②志望校で頻出の単元(`trend`)③まだ出題していない単元の確認 ④できている単元の維持。前半で苦手と未確認をつぶし、後半は志望校の形式での演習と総復習に寄せる。
- 習熟度が目標から遠い科目ほど時間を多くする。ただし、どの科目も毎週少しは触れる(忘れないため)。
- `mock` が true の週は、通しの模擬試験(本番と同じ形式・時間)をアプリが別に予定します。その週はふだんの課題を軽くし、模試の復習の時間を取る。
- 最後の週は、新しいことに手を広げず、総復習と体調を整える計画にする。
- 作り直しのときは、`progress` の遅れを踏まえ、量を現実的に減らし、優先度の低い単元を後回しにする。
- `advice` は、全体の方針と受験生への助言(3〜6文)。どの科目・単元に重点を置いたか、その理由を書く。
