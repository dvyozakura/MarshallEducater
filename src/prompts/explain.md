# 間違えた問題の解説

科目「{{subjectName}}」のテスト「{{testTitle}}」で、受験生が間違えた(満点でなかった)問題の **解説** を書いてください。受験生が一人で読んで、次は自力で解けるようになることが目的です。

入力ファイルの内容:

- `project` … 志望校・試験の型・目標の高さ。
- `items` … 解説を書く設問の一覧。設問ごとに:
  - `problemId`、`number`、`format`(choice / short / essay)、`unitName`、`difficulty`、`points`
  - `body`(問題文)、`choices`(選択肢)、`key`(正解・模範解答)、`rubric`(採点基準)、`solution`(作問時の解き方のメモ)
  - `answer` … 受験生の答案(空なら未解答)。選択式は選んだ番号。
  - `score` … 得点、`mistake` … ミスの種類、`rationale` … 採点の根拠、`comment` … 採点時の所見。

## 書く内容(設問ごとに3つ)

- `thinking` … **考え方**。問題文のどこに注目し、どの知識・定理・方針を選ぶか。「なぜその方針になるのか」を書く(2〜5文)。
- `solution` … **解き方**。正解にたどり着くまでの手順を、途中の式や根拠を省かずに順に書く。選択式は、正解の理由に加えて、受験生が選んだ選択肢がなぜ違うのかも書く。記述は、採点基準のどこで点が入るかが分かるように書く。
- `tip` … **同じミスを防ぐ一言**。この受験生の答案とミスの種類(`mistake`)に合わせた、具体的で短い助言(1〜2文)。「気をつけよう」のような一般論だけにしない。

## 決まり

- `items` の **すべての設問** について、同じ `problemId` で1つずつ書く。
- `key` と `solution` に合う内容にする。もし `key` が誤っていると判断した場合は、その旨と理由を `solution` の最初に明記する(黙って別の答えにしない)。
- 受験生の答案に触れるときは、書かれている内容だけをもとにする。未解答なら「最初の一歩」をどう踏み出すかを `thinking` で丁寧に書く。
- 文章は Markdown、数式は LaTeX(`$...$`、`$$...$$`)。見出し(`#`)は使わない。
- 目標の高さに合った水準で書く。教科書に載っている基本事項も、必要なら一言で補う。
